# 毕业答辩说明稿

## 一句话介绍

本系统是一个面向自学场景的个性化学习辅助系统。它通过大语言模型、知识图谱和向量检索技术，分析学生的学习目标、学习材料和答题表现，自动生成诊断题、薄弱点记录和自适应学习路径。

## 研究背景

传统自学平台通常提供固定课程目录，学习者只能按统一顺序学习。实际自学过程中，不同学生的基础、学习目标、时间安排和问题点差异很大。如果系统不能识别学生的薄弱环节，就很难给出真正有针对性的学习建议。

因此，本系统尝试解决三个问题：

1. 如何从学习材料中自动提取知识点和概念关系。
2. 如何根据学生的目标和答题结果判断薄弱点。
3. 如何生成可以动态调整的个性化自学路径。

## 系统核心流程

1. 用户填写学习目标、学科、阶段、学习偏好和当前问题。
2. 用户上传学习材料，系统将材料切分并写入向量数据库。
3. 系统提取关键概念，构建概念之间的关系结构。
4. 大模型结合用户画像和材料生成诊断题。
5. 学生答题后，系统记录错误点和薄弱知识点。
6. 系统生成个性化学习路线。
7. 后续练习围绕薄弱点继续抽题，并持续更新学习状态。

## 系统创新点

- 不是固定课程表，而是根据学习者状态动态生成路径。
- 同时使用向量数据库和知识图谱，分别处理文本语义和概念关系。
- 通过诊断题把学生状态转化为可记录的薄弱点。
- 支持后续练习和问答，不是一次性生成结果。
- 前端采用递进式交互，更符合真实学习流程。

## 演示顺序

1. 打开首页，输入学习目标。
2. 选择学习偏好，进入材料页面。
3. 粘贴一段课程材料，点击整理材料。
4. 进入分析页面，展示系统如何判断问题。
5. 开始诊断，回答几道题。
6. 展示生成的学习路线。
7. 进入练习页面，演示围绕薄弱点继续抽题。
8. 进入助教页面，提问并展示 RAG 回答。

## 可能被问到的问题

### 1. 为什么要用知识图谱？

学习内容之间存在前置、包含、关联等关系。知识图谱可以显式表达这些关系，帮助系统判断学习顺序，而不是简单按文本顺序推荐内容。

### 2. 为什么还要用向量数据库？

知识图谱适合存概念关系，向量数据库适合存大段自然语言材料。学生上传的笔记、教材片段和题目说明更适合用向量检索找到相关内容。

### 3. RAG 在系统中的作用是什么？

RAG 让大模型回答时先参考用户上传的材料，减少模型脱离材料自由发挥的问题。系统先检索相关片段，再把片段、用户画像和问题一起交给模型。

### 4. 个性化体现在哪里？

体现在学习目标、年级阶段、学习偏好、当前问题、诊断答题结果和薄弱点记录。不同用户即使学习同一主题，也会得到不同的诊断题和学习路径。

### 5. 大模型是否会生成错误内容？

存在这种可能。系统通过结构化提示词、材料检索和本地兜底逻辑降低风险。后续可以加入教师审核、答案校验和题库约束。

### 6. Neo4j 和 ChromaDB 分别做什么？

Neo4j 用于存储知识点节点和关系边，例如“损失函数”与“模型训练”的关系。ChromaDB 用于存储文本片段向量，支持语义检索。

### 7. 系统难点在哪里？

难点不是单独调用模型，而是把用户画像、材料检索、知识关系、诊断结果和路径规划串成完整流程，并保证每一步都能影响后续结果。

### 8. 后续如何改进？

可以增加教师端管理、学习长期记忆、Neo4j 图谱可视化、真实评分模型、多轮学习报告和课程资源自动检索。
